Instrukcja tagowania HTML dla Perplexity AI

Wersja 1.0 · Quolino/Questini · Sierpień 2026

CEL: Perplexity AI generuje plik HTML z treścią wycieczki po mieście. Każdy element treści musi mieć atrybut id lub data-field identyczny z nazwą kolumny w bazie danych Supabase. Dzięki temu import do bazy jest automatyczny — parser czyta HTML, wyciąga wartości po atrybutach i wstawia do odpowiednich tabel.

2. Konwencja nazewnictwa ID

Każdy element HTML z treścią do importu musi mieć atrybut id zbudowany wg wzorca:

id="{stop_key}--{nazwa_kolumny}"

Separator to podwójny myślnik -- (odróżnia go od myślników w stop_key).

Przykłady:

id="basilica-santa-chiara--name"
id="basilica-santa-chiara--desc_paragraphs"
id="basilica-santa-chiara--kids_box"
id="basilica-santa-chiara--hint"
id="basilica-santa-chiara--local_flavor"
id="basilica-santa-chiara--photo_task"
id="basilica-santa-chiara--dress_code"
id="basilica-santa-chiara--practical_note"
id="basilica-santa-chiara--time_label"
id="basilica-santa-chiara--visit_duration"
id="basilica-santa-chiara--year_built"
id="basilica-santa-chiara--price"
id="basilica-santa-chiara--opening_hours"
id="basilica-santa-chiara--maps_query"
id="basilica-santa-chiara--verify_url"
id="basilica-santa-chiara--sources"
ZASADA: Nazwy kolumn w atrybucie id muszą być dokładnie identyczne z nazwami kolumn w bazie danych. Nie tłumacz, nie zmieniaj wielkości liter, nie zamieniaj podkreślników na myślniki. desc_paragraphs — nie descParagraphs, nie desc-paragraphs, nie opis.

3. Wymagana struktura pliku HTML

<!doctype html>
<html lang="pl">
<head>
  <meta charset="utf-8">
  <title>{PAŃSTWO}-{Region}-{Miasto}-v{NN}</title>
</head>
<body>

  <!-- 1. META: dane miasta -->
  <section id="city-meta"> ... </section>

  <!-- 2. STOPS: przystanki (powtarzalny blok) -->
  <article id="stop--{stop_key}" data-stop-number="{N}" data-category="{cat}">
    ...
  </article>

  <!-- 3. EMERGENCY: punkty awaryjne -->
  <section id="emergency-points"> ... </section>

  <!-- 4. DAY PLAN: generowany automatycznie z stops -->

  <!-- 5. JSON-LD: dane strukturalne -->
  <script id="questini-data" type="application/json">
    { ... }
  </script>

</body>
</html>

5. Sekcja STOP — przystanek

Każdy przystanek to jeden <article>. Wewnątrz — divy z treścią, każdy z id mapującym na kolumnę.

Pełna struktura bloku przystanku:

<article id="stop--basilica-santa-chiara"
         data-stop-number="2"
         data-category="church"
         data-optional="false">

  <!-- === NAGŁÓWEK === -->
  <h2 id="basilica-santa-chiara--name">Basilica di Santa Chiara</h2>

  <!-- === SEKCJA A: DANE PRZYSTANKU (tabela stops) === -->
  <div class="stop-data">
    <div id="basilica-santa-chiara--stop_key">basilica-santa-chiara</div>
    <div id="basilica-santa-chiara--maps_query">Basilica di Santa Chiara, Piazza Santa Chiara, Assisi, Italy</div>
    <div id="basilica-santa-chiara--time_label">10:30</div>
    <div id="basilica-santa-chiara--visit_duration">~45 min</div>
    <div id="basilica-santa-chiara--year_built">1257–1265</div>
    <div id="basilica-santa-chiara--price">wolny (krypta €3)</div>
    <div id="basilica-santa-chiara--opening_hours">6:30–12:00, 14:00–18:30 (lato do 19:00)</div>
    <div id="basilica-santa-chiara--verify_url">https://www.assisisantachiara.it/</div>
    <div id="basilica-santa-chiara--phone">+39 075 812282</div>
    <div id="basilica-santa-chiara--website">https://www.assisisantachiara.it/</div>
    <div id="basilica-santa-chiara--ztl"></div>
    <div id="basilica-santa-chiara--reservation"></div>
  </div>

  <!-- === SEKCJA A2: DRESS CODE + PRACTICAL NOTE (tabela stop_translations) === -->
  <div id="basilica-santa-chiara--dress_code">kościelny — kolana i ramiona zakryte</div>
  <div id="basilica-santa-chiara--practical_note">Bilety online nie są wymagane.</div>

  <!-- === SEKCJA B: RODZIC — OPIS (stop_translations.desc_paragraphs) === -->
  <div id="basilica-santa-chiara--desc_paragraphs">
    <p>Pierwszy akapit opisu dla rodzica. Każdy tag &lt;p&gt; to osobny
    element tablicy desc_paragraphs w bazie.</p>
    <p>Drugi akapit opisu...</p>
    <p>Trzeci akapit opisu...</p>
    <!-- dowolna liczba <p>, każdy = osobny element tablicy -->
  </div>

  <!-- === SEKCJA C: DZIECKO — QUEST (stop_translations.kids_box) === -->
  <div id="basilica-santa-chiara--kids_box">
    <p>Informacja dla dziecka gdzie jest i co widzi.</p>
    <p>Ciekawostka: jedna konkretna ciekawostka.</p>
    <p>Quest: Opis zadania do wykonania na miejscu.</p>
  </div>

  <!-- === SEKCJA C2: ZADANIE FOTO (opcjonalne) === -->
  <div id="basilica-santa-chiara--photo_task">Zrób zdjęcie...</div>

  <!-- === SEKCJA D: WSKAZÓWKA (stop_translations.hint) === -->
  <div id="basilica-santa-chiara--hint">Szukaj krucyfiksu po lewej stronie nawy...</div>

  <!-- === SEKCJA E: LOKALNY SMAK (stop_translations.local_flavor) === -->
  <div id="basilica-santa-chiara--local_flavor">Na placu przed bazyliką...</div>

  <!-- === SEKCJA F: ŹRÓDŁA (stops.sources) === -->
  <div id="basilica-santa-chiara--sources">
    <a href="https://en.wikipedia.org/wiki/...">Wikipedia — Basilica di Santa Chiara</a>
    <a href="https://www.assisisantachiara.it/">Oficjalna strona bazyliki</a>
  </div>

  <!-- === SEKCJA G: UWAGA OGÓLNA (editorial_notes, nie importowana do frontendu) === -->
  <div id="basilica-santa-chiara--editorial_note" class="editorial">
    Uwagi redakcyjne, notatki wewnętrzne. Ten blok NIE jest importowany
    do publicznej bazy — służy wyłącznie redakcji.
  </div>

</article>
KLUCZOWE REGUŁY SEKCJI B (desc_paragraphs):
• Każdy <p> wewnątrz diva --desc_paragraphs staje się osobnym elementem tablicy w bazie.
• Nie skracaj, nie łącz paragrafów. Jeśli tekst ma 15 akapitów — wstaw 15 tagów <p>.
• Nagłówki <h4> wewnątrz opisu traktuj jako wyróżnienie — wstaw jako <p><strong>Nagłówek</strong></p> — osobny element tablicy.
• Tekst ma być bogaty, merytoryczny, 8–15 akapitów dla głównych zabytków.

11. Reguły redakcyjne

Sekcja B — opis dla rodzica (desc_paragraphs)

• Bogate, wieloparagrafowe opisy: 8–15 akapitów dla kluczowych zabytków (katedry, bazyliki, twierdze), 3–5 dla punktów prostszych (parking, lodziarnia, powrót).

• Każdy <p> = osobny element tablicy w bazie. Nie łącz paragrafów.

• Jeśli w opisie są podtematy (Historia, Co zobaczyć, Praktyka) — wstaw je jako <p><strong>Historia</strong></p> — osobny element tablicy.

• Legendy i tradycje hagiograficzne wyraźnie oznaczaj: "według tradycji", "legenda głosi".

• Źródłowo prawdziwe — sprawdzone daty, fakty, ceny.

Sekcja C — quest dla dziecka (kids_box)

• Krótka informacja: "Jesteś w [miejsce]. To [co to jest, 1–2 zdania]."

• Ciekawostka: jeden konkretny, zaskakujący fakt.

• Quest: faktyczne zadanie do wykonania na miejscu — obserwacja, znalezienie detalu, porównanie, dedukcja. Nie "dowiedz się" (to nudne), ale "znajdź", "policz", "porównaj", "wskaż".

Sekcja D — wskazówka (hint)

• Jedna, konkretna wskazówka pomagająca dziecku rozwiązać quest. Nie odpowiedź, ale naprowadzenie.

Sekcja E — lokalny smak (local_flavor)

• Jedna ciekawostka z okolicy: legenda, anegdota, ciekawostka ekonomiczna, tradycja lokalna.

Nazewnictwo pliku

Format: {PAŃSTWO}-{Region}-{Miasto}-v{NN}.html

Przykłady: IT-Umbria-Assisi-v07.html, IT-Umbria-Spello-v31.html, HR-Istra-Rovinj-v01.html

1Wszystkie id unikalneKażdy id w dokumencie musi być unikalny. Wzorzec: {stop_key}--{kolumna}.

8JSON-LD blok na doleBlok <script id="questini-data"> z pełnymi danymi strukturalnymi.
9Emergency: min. 5 pozycji2× apteka, 1× toalety, 1× plac zabaw, 1× szpital.
10Frazy: min. 8 zwrotówPowitania, jedzenie, zakupy, pomoc, dzieci.
